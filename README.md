# Heretous

Чатрулетка для групповых видеозвонков.

Go HTTP-сервер, Vue-фронтенд на TypeScript, PostgreSQL, SQL-миграции, гостевой вход и сессии. Комнаты и видеозвонки пока не реализованы.

Для входа достаточно имени. Сессия хранится в HttpOnly-cookie; секреты не записываются в `localStorage`.

## Требования и запуск

Для запуска всего продукта нужен Docker Engine с Compose v2. Go и PostgreSQL на компьютере не требуются. Команды выполняются из корня репозитория.

Compose собирает локальный образ `heretous:local` из Dockerfile с актуальными Go-кодом, миграциями и Vue-фронтендом при каждом запуске, используя кеш Docker. Файл `.env` для запуска не требуется.

```sh
docker compose up
```

Страница входа: `http://localhost:8080/`. PostgreSQL доступен на `127.0.0.1:5432`, данные сохраняются в томе `postgres-data`. Перед запуском HTTP приложение применяет миграции.

Для запуска в фоне с ожиданием готовности используйте `docker compose up --wait --wait-timeout 120`.

```sh
curl http://localhost:8080/healthz
curl http://localhost:8080/readyz
```

`/healthz` возвращает 200, пока работает HTTP-сервер. `/readyz` дополнительно проверяет PostgreSQL и возвращает 503 при недоступной БД. Compose использует `/readyz` для проверки готовности.

Остановка: `docker compose stop`. Сервер ждёт активные запросы в течение `shutdown_timeout`, затем закрывает соединения и пул БД.

## Конфигурация

Таймауты, срок сессии и параметры пула читаются только из [`config.yaml`](config.yaml); в Compose файл монтируется только для чтения. Настройки окружения читаются только из env. Неизвестные ключи YAML и некорректные значения останавливают запуск.

Значения из YAML не дублируются в Go. Таймауты и `database.max_open_connections` должны быть положительными. `database.max_idle_connections` допускает ноль и не превышает `database.max_open_connections`; `session.ttl` — положительное целое число секунд.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `CONFIG_PATH` | `config.yaml` | Путь к обязательному YAML-файлу, относительно рабочего каталога |
| `HTTP_ADDR` | `:8080` | Адрес и порт HTTP-сервера; `127.0.0.1:8080` для доступа только с этого компьютера |
| `LOG_LEVEL` | `INFO` | Уровень логирования: `DEBUG`, `INFO`, `WARN`, `ERROR` |
| `DATABASE_URL` | Нет, обязательна | Строка подключения PostgreSQL |
| `SESSION_COOKIE_SECURE` | `false` | `true` для HTTPS в staging/prod, включая TLS на балансировщике; `false` для локального HTTP |
| `WEB_DIR` | `web/dist` | Каталог собранного Vue-фронтенда, который раздаёт Go |

Приложение не загружает `.env`: Compose использует его для подстановок. `POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD` задают локальную БД и формируют `DATABASE_URL`; по умолчанию все три равны `heretous`. В локальном Compose `LOG_LEVEL` по умолчанию равен `DEBUG`, `SESSION_COOKIE_SECURE` — `false`. Для изменения настроек скопируйте `.env.example` в `.env` и отредактируйте значения. Специальные символы в учётных данных должны быть совместимы с URI. Изменение этих переменных не меняет учётные данные в уже созданном томе PostgreSQL.

Другой env-файл можно выбрать через `docker compose --env-file .env.local up --wait --wait-timeout 120`. Файлы `.env` и `.env.*` исключены из Git, кроме `.env.example`. Переменные текущего shell имеют приоритет над подстановками из env-файла Compose.

Для staging и prod используйте тот же образ, передавая переменные средствами деплоя. Другой YAML можно подключить через `CONFIG_PATH`. Этот Compose предназначен для локального окружения с сервисом `postgres`.

При локальном запуске с установленным Go 1.25+ сначала запустите PostgreSQL, затем сервер. Миграции он применит автоматически. Пример для PowerShell:

```powershell
$env:DATABASE_URL = 'postgres://heretous:heretous@localhost:5432/heretous?sslmode=disable'
go run ./cmd/server
```

Логи пишутся в stdout в формате JSON. `Ctrl+C` или `SIGTERM` инициирует штатное завершение сервера.

## Гостевой вход и сессии

Страница входа находится на `/`. `POST /api/auth/guest` принимает JSON `{"name":"Саша"}` и возвращает 201 с `{"user":{"id":"…","name":"Саша","is_guest":true},"expires_at":"…"}`. Имя содержит от 1 до 32 Unicode-символов, пробелы нормализуются; управляющие и невидимые форматирующие символы запрещены. Имена не обязаны быть уникальными.

Ответ устанавливает cookie `heretous_session` с `HttpOnly`, `SameSite=Lax` и `Path=/`. `GET /api/session` возвращает пользователя и срок сессии либо 401. `DELETE /api/session` отзывает сессию в БД, удаляет cookie и возвращает 204; повторный выход допустим. Повторный гостевой вход создаёт нового пользователя и атомарно заменяет старую сессию. API не кэшируется; небезопасные запросы с другого origin блокируются.

Срок сессии задаётся только в YAML: `session.ttl: 720h` (30 дней), положительное целое число секунд. На HTTPS задайте `SESSION_COOKIE_SECURE=true` на всех экземплярах, в том числе при TLS на балансировщике. Заголовки `X-Forwarded-*` не используются для определения безопасности cookie.

Секрет сессии содержит 32 случайных байта. PostgreSQL хранит только SHA-256-хеш токена; срок действия проверяется по времени БД. Все экземпляры Go используют одну БД и одинаковые настройки cookie, без локального хранилища сессий, общих ключей подписи или sticky sessions. Миграции при одновременном старте сериализуются advisory-блокировкой. Балансировщик направляет фронтенд и `/api` через один публичный origin. Локальный Compose публикует фиксированный порт для одного экземпляра; при масштабировании порты и балансировщик задаются в окружении деплоя.

## Фронтенд

Vue-приложение в `web/` восстанавливает сессию после перезагрузки страницы, показывает форму имени или приветствие и позволяет выйти. При недоступном API показывает ошибку и повтор запроса. JavaScript не имеет доступа к токену сессии.

Для разработки нужен Node.js `^22.18.0 || >=24.12.0`. Команды ниже предназначены для ручного запуска; сборка и тесты агентом выполняются только по явному запросу.

```sh
cd web
npm ci
npm run dev
```

Vite слушает `http://127.0.0.1:5173` и проксирует `/api` на Go-сервер `http://127.0.0.1:8080`, сохраняя исходный Host для проверки origin. БД и Go-сервер запускаются отдельно. `npm run typecheck` проверяет типы TypeScript и Vue-компонентов. `npm run build` сначала проверяет типы, затем создаёт `web/dist`, который раздаёт Go; без этого каталога API работает, а страница возвращает 503. Dockerfile собирает Vue и копирует результат в runtime-образ. При `docker compose up` образ с актуальными Go-кодом, миграциями и фронтендом собирается автоматически.

## Миграции

SQL-миграции из `migrations/` встроены в Go-бинарник и применяются через Goose до запуска HTTP. Advisory-блокировка PostgreSQL сериализует миграции нескольких экземпляров. `migration_timeout` ограничивает ожидание блокировки и выполнение SQL; ошибка останавливает запуск.

Первая миграция создаёт схему `app`; вторая — таблицы `app.users` и `app.sessions`. Следующие файлы добавляйте с номера `00003` с секциями `-- +goose Up` / `-- +goose Down`; для применения новых файлов пересоберите образ. Уже применённые миграции не изменяйте. `migration_timeout` ограничивает ожидание блокировки и выполнение миграций при старте сервера. Истёкшие сессии не проходят авторизацию; их строки можно периодически удалять по `expires_at` средствами обслуживания БД.

Миграции должны быть совместимы с ещё работающей предыдущей версией приложения. Учётной записи приложения нужны права на изменение структуры БД.

## Образ Docker

Dockerfile собирает Vue и Go в отдельных этапах. Runtime работает от непривилегированного пользователя. При изменении `shutdown_timeout` согласуйте `stop_grace_period` в Compose.

Период `healthcheck.start_period` приложения равен 65 секундам с учётом стандартного `migration_timeout: 1m` и подключения к БД. При увеличении времени миграций согласуйте этот период и `--wait-timeout`. Фиксированный опубликованный порт предназначен для одного локального инстанса; для нескольких инстансов нужны отдельные порты или балансировщик.
