# Heretous

Чатрулетка для групповых видеозвонков. Описание идеи — в файле `readme`.

Первый этап: HTTP-сервер с конфигурацией, структурированными логами и корректным завершением. Бизнес-логика пока не реализована.

## Требования и запуск

Go 1.25 или новее. Внешних зависимостей нет.

```sh
go run ./cmd/server
```

По умолчанию сервер слушает `:8080`. Проверка доступности:

```sh
curl http://localhost:8080/healthz
```

Ответ: HTTP 200, `{"status":"ok"}`. Неизвестные пути возвращают 404, неподдерживаемые методы — 405.

## Конфигурация

Значения читаются из окружения при запуске. Пустые значения используют настройки по умолчанию. Файл `.env` автоматически не загружается.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `HTTP_ADDR` | `:8080` | Адрес и порт HTTP-сервера; `127.0.0.1:8080` для доступа только с этого компьютера |
| `HTTP_SHUTDOWN_TIMEOUT` | `10s` | Положительное время ожидания текущих запросов при завершении |
| `LOG_LEVEL` | `INFO` | Уровень логирования: `DEBUG`, `INFO`, `WARN`, `ERROR` |

Пример для PowerShell:

```powershell
$env:HTTP_ADDR = '127.0.0.1:8081'
$env:LOG_LEVEL = 'DEBUG'
go run ./cmd/server
```

Логи пишутся в stdout в формате JSON. Для HTTP настроены таймауты: чтение заголовков — 5 секунд, чтение запроса — 10 секунд, запись ответа — 15 секунд, простой соединения — 60 секунд.

## Сборка и остановка

```sh
go build -o bin/server ./cmd/server
```

На Windows:

```powershell
go build -o bin/server.exe ./cmd/server
.\bin\server.exe
```

`Ctrl+C` или `SIGTERM` запускает завершение: сервер перестаёт принимать соединения и ждёт текущие запросы до `HTTP_SHUTDOWN_TIMEOUT`. После истечения срока соединения закрываются принудительно. Штатное завершение возвращает код 0; ошибка конфигурации, запуска или завершения — код 1. Для работы с сигналами запускайте собранный бинарный файл напрямую: поведение передачи сигналов через `go run` зависит от платформы.

## Структура

```text
cmd/server/       точка входа, логирование, обработка сигналов
internal/config/  чтение и проверка конфигурации
internal/app/     запуск и завершение HTTP-сервера
internal/httpapi/ маршруты и HTTP-обработчики
```

## Проверки

Для проверок через Docker нужен Docker Engine с Compose v2; Go на компьютере не требуется. Выполняйте команды из корня репозитория:

```sh
docker compose -f docker-compose.yml run --build --rm -T tests
```

Сервис `tests` имеет метку `com.heretous.task=test` и профиль `test`, поэтому обычный `docker compose up` его не запускает. При явном указании сервиса профиль активируется автоматически. Команда проверяет код через `go vet` и запускает тесты с детектором гонок, без кэша результатов и с ограничением 60 секунд на пакет. Кэши сборки и Go-модулей сохраняются в именованных томах. Исходники копируются в образ; `--build` нужен, чтобы учесть изменения.

Запуск отдельной группы тестов:

```sh
docker compose -f docker-compose.yml run --build --rm -T tests go test -race -count=1 -timeout=60s -run TestShutdown ./internal/app
```

Скилл для этого процесса находится в [`.agents/skills/heretous-tests/SKILL.md`](.agents/skills/heretous-tests/SKILL.md); имя для вызова — `$heretous-tests`.

При установленном Go проверки также доступны напрямую:

```sh
go test ./...
go vet ./...
```

## Приложение в Docker

```sh
docker compose up --build -d app
curl http://localhost:8080/healthz
docker compose stop app
```

`Dockerfile` содержит этапы `development` (Go и инструменты сборки), `test` (проверки), `build` (статический бинарный файл) и `runtime` (приложение и корневые сертификаты). Финальный образ запускает сервер от непривилегированного пользователя. Compose публикует порт 8080 только на `127.0.0.1` и даёт приложению 15 секунд для завершения, при внутреннем таймауте 10 секунд.
